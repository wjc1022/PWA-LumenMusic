# PrivateKara 开发路线图

## 当前产品基线

PrivateKara 是用户自备媒体、优先本地使用的卡拉 OK PWA。当前代码已实现：

- 本地音频／视频导入与播放、音乐库及歌单管理。
- 同步 LRC 歌词；已有 Enhanced LRC 逐字标签解析、当前词及已唱词高亮。
- 音频原唱／伴奏切换，尝试保留位置和播放状态；不承诺无缝切换，MV 尚不支持。
- JSON 与 `.lmp` 本地备份和恢复。
- 本地最近播放记录与播放次数；目前按选歌流程记账，尚不能代表有效演唱次数。

功能详情和使用限制见 [README.md](../README.md)。以上是代码实现基线，不代表真实 iPhone、Safari 或安装后 PWA 已验收；历史自动化结果见[开发历史归档](history/DEVELOPMENT_HISTORY.md)，不作为本轮设备验证结果。

## 已知问题与稳定性

- **已确认的实现限制：** 现有播放记录和计数没有有效演唱判定，短暂播放或重复选歌可能计入；需按后续独立任务完善。
- **曾发生、尚未确认解决的故障：** iPhone PWA 重启后媒体不可读、播放中途停滞、实际原唱／伴奏文件对定位异常，以及 `.lrc`／`.txt` 文件选择问题。历史诊断曾记录 IndexedDB Blob 首尾读取 `NotFoundError` 和写入 `Error preparing Blob/File data to be stored in object store`。媒体与日常属性已拆分保存，但不能据此断言设备根因已解决或旧故障资源可恢复。保留故障条目和诊断证据，避免以重导入掩盖问题。
- **潜在风险及升级限制：** 浏览器配额、存储回收、站点数据清除和设备故障可能使本地资料丢失；浏览器存储不能替代备份。当前 `lumen-db` v2 升级会清空旧应用数据库，需重新导入；JSON／`.lmp` 当前格式版本为 3，旧版备份被拒绝。后续升级需评估兼容性、失败处理和数据丢失风险。
- **待真机验证：** 分别验证 iOS Safari 与安装后 PWA 的文件导入、Blob 多日持久化及重启读取、实际可听输出、持续播放、原唱／伴奏切换、歌词同步与定位、前台常亮、触摸、安全区域、全屏／方向和场所屏幕镜像。桌面自动化、元数据可加载或进度推进均不能替代这些验收。

## 后续开发任务

以下任务相互独立，不规定固定实施顺序或交付日期。

### A. Enhanced LRC 逐字歌词完善

已有逐字解析与高亮实现；验证并完善显示、同步、前后定位、原唱／伴奏切换时的表现和真机可用性。

### B. MV 原唱／伴奏切换

支持视频／MV 播放期间切换用户提供的原唱与伴奏，并保持视频、音频和歌词适当同步；具体架构待实施时确定。

### C. 个人网盘媒体访问

从个人网盘导入用户自有媒体与歌词，在技术可行时支持直接流式播放；明确授权、资源可用性及离线行为。此任务独立于个人记录持久化。

### D. 有效播放记录与次数优化

播放历史同时作为卡拉 OK 演唱历史，不引入独立的 KTV Session 概念。避免将极短播放、重复点击算作多次演唱，并防止暂停／继续、定位及快速切歌引起重复计数；具体阈值和计数规则在实施时确定。

### E. 个人记录云端持久化

优先采用 local-first 方式，使用个人云存储备份和恢复播放历史、次数及相关音乐库元数据，支持长期保留、换机及浏览器本地数据丢失后的恢复。此任务独立于云媒体导入／流式播放，不预设专有后端、强制账号体系或复杂多设备同步。

### 其他仍相关的历史规划

歌曲资料编辑、自定义属性、歌单与队列来源及变更行为、仅资料导出与回导仍有未完成规划；具体旧方案保留在[开发历史归档](history/DEVELOPMENT_HISTORY.md)的“数据存储、歌曲资料与歌单改造规划”中，实施前核对当前代码并确认范围，不将历史建议直接视为已定需求。

## 长期想法（非承诺）

- 手机控制与电视展示分离的体验。
- 更丰富的卡拉 OK 展示与控制增强。

以上仅为可选、低优先级想法，不构成近期架构要求或其他任务的实施依赖。

## 不在项目范围内

PrivateKara 不提供音乐、MV、伴奏或歌词的发现与分发服务，不内置 AI 人声分离或歌词生成，也不要求集中式媒体目录或后端。用户自行准备并提供媒体资源；归档中曾讨论的生成服务属于历史记录，不纳入当前路线图。
